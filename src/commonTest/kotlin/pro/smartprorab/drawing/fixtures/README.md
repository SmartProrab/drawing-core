# Фикстуры чертежей

`MeasureFixtures.kt` — 170 реальных чертежей из `rv_measure` (выгрузка 23.10.2026), дубли геометрии убраны. Фикстуры встроены строками, а не ресурсами, чтобы одинаково работать на всех таргетах `commonTest`.

## Категории

| Тег | Кол-во | Что проверяет |
|---|---|---|
| `RANDOM` | 146 | текущие данные (`room_id >= 1100000`): площадь и периметр по правилу из #2 совпадают с сохранёнными во всех 146 случаях |
| `BOUNDARY` | 8 | площадь ровно `x.x5` м²: новое правило half-up даёт на 0,1 больше, чем сохранил старый web |
| `REVERSE` | 7 | обход против нормализованного; все — legacy (`room_id` < 600k) |
| `DEGENERATE` | 6 | нулевая площадь; сохранять нельзя |
| `EMPTY` | 3 | контур с пустым `points`; у двух комнат он соседствует с нормальным контуром |

## Особые случаи

- **585337** — обратный обход и устаревшие `area`/`perimeter` (11,1 / 18,0 при 3,6 / 8,7 по точкам).
- **191994, 237594, 808705** — legacy-контуры из 2 точек, но с ненулевыми сохранёнными площадью и периметром: геометрия потеряна.
- **1050856, 1088654, 1087391** — текущие «пустые» контуры: все точки совпадают или росчерк в 1 см.
- **1124560** — площадь 5,95145 м² по точкам, сохранено 5,9 (устаревшее значение, см. #4).

## Наблюдения по выборке

- Ни одной комнаты с 2+ непустыми контурами среди `room_id >= 1100000`: текущие клиенты такие чертежи, похоже, не создают.
- Пустые контуры встречаются в текущих данных рядом с нормальным — вероятно, «добавил контур и не нарисовал».

## Порядок координат

В JSON точка — `[вертикаль, горизонталь]` (контракт Leaflet в web). В домене x — вправо, y — вверх. `orientationSign` дан в доменных координатах: нормализованный обход web — по часовой, т. е. `-1`.

## Правило ожидаемых значений

- координаты → целые мм: `round(cm * 10)`;
- `areaTenthsM2 = (abs(twiceAreaMm2) + 100_000) / 200_000`;
- `perimeterTenthsM = floor(sumOfSidesMm / 100 + 0.5)`;
- `savable` = не меньше 3 вершин и ненулевая площадь.
